# 2026-11-12 — P4: voice in, summary out, free engines only

Push-to-talk in, a two-sentence summary out, and no paid realtime service. ADR-005, built and measured.

## Pipeline

```
browser mic (MediaRecorder)
   │ multipart audio
   ▼
POST /api/voice/transcribe        irisd, cookie-authenticated
   │ raw bytes                      (the sidecar is never exposed)
   ▼
voice sidecar 127.0.0.1:3310
   │ ffmpeg -> 16 kHz mono wav -> float32 array
   │ faster-whisper small (one request at a time)
   ▼
{text, ms} ──► composer, editable, NOT auto-sent

assistant reply ──► Speaker button / auto-speak
   │ POST /api/voice/speak {text}
   ▼
irisd ──► sidecar ──► normalise_for_speech()
                       strip markdown, drop code/tables, redact secrets,
                       expand numbers, keep <=2 sentences
   ▼
edge-tts id-ID-GadisNeural -8% ──► audio/mpeg + X-Iris-Spoken-Text
```

`X-Iris-Spoken-Text` is the exact sentence(s) handed to edge-tts. The test asserts it contains no
`*`, `#`, backtick, `|`, URL or code, which is stronger than looking at the audio.

## A. `voice/` sidecar

- Python 3 + aiohttp on `127.0.0.1:3310`. Run with the existing voice-HUD venv; no second venv and no
  install step:
  `~/Documents/projects/voice-hud/bridge/.venv/bin/python voice/server.py`.
- `POST /transcribe` reads raw bytes, sniffs the container from magic bytes (webm, ogg, wav, mp3, mp4),
  decodes with ffmpeg to 16 kHz mono, reads int16 into a float32 array and calls faster-whisper `small`
  (`language=id`, `beam_size=1`, VAD on). Its own PyAV decoder is fragile on Python 3.14, so it never
  sees a path.
- An empty body, a quick tap, a decode failure or silence all answer **200**
  `{"text":"","reason":"no_speech"}`. No 500 is possible on that path.
- `POST /speak` normalises first, then streams edge-tts. Empty text is 400; an unspeakable reply returns
  200 with an empty body and an empty spoken header.
- `GET /health` returns `{ok, model, voice, warm}`.
- Warm at boot: model load and one throwaway synthesis, both logged. STT is guarded by one `asyncio.Lock`
  (CTranslate2 is not thread-safe); TTS may overlap. One aiohttp worker.

## B. Sanitiser (`voice/normalise.py`, pure, 27 tests)

Rules copied from `~/Documents/projects/voice-hud/bridge/normalise.py` (the tested HUD normaliser) and
extended for Iris. Nothing is imported across projects; the comment at the top says where the rules came
from.

| Input | Spoken result |
|---|---|
| `**teks**`, `# heading`, backticks | markup removed, inline-code text kept |
| `[label](url)` | `label`; bare URLs dropped |
| bullets / numbered items | sentence breaks (`- satu` -> `satu.`) |
| fenced code | dropped entirely; “kodenya ada di layar” at most once |
| markdown tables | dropped entirely; “tabelnya ada di layar” when nothing else is left |
| file paths, `sk-…`, `bot…:…`, long hex | dropped or “kunci rahasia” |
| `12%`, `Rp50.000`, `16 GB`, `→` | “dua belas persen”, “rupiah lima puluh ribu”, “enam belas gigabita”, “menjadi” |
| long answer | first sentence + outcome, detail clause folded into the second sentence: `detailnya ada di layar.` |

The summary is two sentences maximum and aims for ~220 characters. It never cuts mid-word: when a reply
is too long it selects whole sentences, not substrings. A normal sentence with no markup passes through
unchanged.

## C. `irisd` proxy

- `POST /api/voice/transcribe` (multipart field `audio`, raw body also accepted) -> `{text, ms}`.
- `POST /api/voice/speak` `{text}` -> streams `audio/mpeg`, forwards `X-Iris-Spoken-Text`.
- Both sit behind the same owner cookie as every other route.
- Sidecar down -> `503` with `suara sedang tidak tersedia — coba lagi sebentar.`; the underlying error is
  logged, never sent to the browser.
- `IRIS_VOICE_URL` defaults to `http://127.0.0.1:3310`.

## D. Web

- **Push-to-talk** in the composer: hold on desktop (`pointerdown`/`pointerup`), tap-to-lock on touch.
  Recording shows elapsed seconds, a level meter and **batal**. On stop the transcript lands in the
  composer, editable, and is not sent. A 900-byte floor and an empty-text path make a quick tap an honest
  “terlalu pendek / tidak ada suara”, not a silent failure.
- **Speaker** on every assistant message, plus an **auto-speak** toggle in the room header remembered per
  room in `localStorage` (`iris.autospeak.<room-id>`). While speaking: quiet “membaca…”, and the button is
  a stop button. Auto-speak only speaks new replies, never the history a room opens with.
- **Barge-in**: `voice.start()` calls `speaker.stop()` synchronously, before `getUserMedia` is awaited.
- **Permission denied / no mic** renders Indonesian copy that names HTTPS and Tailscale. No English DOM
  error reaches the screen.
- 44 px targets via `.tap`; the mic is a visible button, never hover-only.

## E. Measured timings (this machine, real engines)

Sidecar boot, from `voice.log`:

| Step | Measured |
|---|---|
| faster-whisper `small` load | **1.30–1.81 s** |
| edge-tts warm-up synthesis | **0.61–0.89 s** |
| total boot before ready | **1.90–2.52 s** |

Warm requests (dedicated timing probe, sidecar on 3311):

| Step | Measured |
|---|---|
| TTS, 24-char phrase, first after warm | **0.77 s** (19.7 KB MP3) |
| TTS, same phrase again | **0.67 s** |
| TTS, 150–180-char two-sentence summary | **0.94–5.32 s** across runs (edge-tts network) |
| STT, 3.2 s MP3, first real request | **2.38 s** |
| STT, same MP3, next request | **1.95 s** |
| STT via `irisd`, 10 s MP3 (P4 acceptance) | **2.67 s** |

**Slowest measured step: edge-tts synthesis.** A two-sentence summary was 0.94 s in one acceptance run and
5.32 s in the timing probe; a 672-char browser reply took 6.6 s, and one 399-char run reached 8.4 s. The
variance is the edge-tts service, not the sanitiser. STT is ~2 s for a short turn, and the browser round trip
from pointer-up to transcript was **2.23 s**.

## J. What could not be verified without a phone

- **A real microphone.** Every check used a synthetic Web Audio stream. Real acoustic input, room noise,
  echo cancellation, gain control and a phone's actual mic level are untested.
- **The real permission flow.** Permission-denied was produced by replacing `getUserMedia`; the browser's
  own permission dialog was not exercised.
- **HTTPS on the device.** `localhost` is a secure context, so the browser check is valid there. A phone
  must use the Tailscale HTTPS hostname; a LAN IP over plain http **cannot** open a microphone. That path
  was not available in this environment.
- **iOS Safari.** MediaRecorder MIME support and playback differ from Chromium; only Chromium 1248 was
  driven.
- **Real speaker barge-in.** Playback was real edge-tts audio in headless Chromium and the pause was
  measured at 0.6 ms, but actual phone speaker latency and audio-focus behaviour were not measured.
- **Auto-speak over a long session.** The per-room preference is stored and read back, but “speak every
  new reply while I walk around” was not lived with.

## Three sanitiser defects found and fixed by the operator

1. **The spoken answer was not actually capped.** With more than two sentences the summariser kept the first
   sentence *and the last*, and the last can be a whole paragraph: measured **~300 characters** spoken, where
   the brief says ≤220 and ≤2 sentences. It now caps at a **word boundary**, never mid-word, and always ends
   with the screen clause.
2. **"AI" was spoken as "ei ai"** (English vowel names) in an Indonesian sentence. It now says
   "kecerdasan buatan"; API/CPU/GPU are spelled with spaced letters instead.
3. **`lama. detailnya ada di layar.`** — the trailing sentence started lowercase. It is capitalised when it
   follows a full stop (the comma-joined variant stays lowercase, which is correct).

Two assertions in the sanitiser suite were also mine to fix: one encoded the old "ei ai" behaviour, and one
of my own new tests wrongly expected `8080` to stay as digits instead of being expanded.
