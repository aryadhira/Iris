# 2026-11-12 — P1a: the Iris backend

## What was built

`irisd` (Go + Echo) on `127.0.0.1:3300`, talking to Hermes' api_server on `:8642` with the bearer key read
from `~/.config/iris-api-key` at boot — never from the repo, never logged.

- **Auth**: single owner, `IRIS_PASSPHRASE` → constant-time compare → 32 random bytes stored as sha256 in
  `auth_sessions`, HttpOnly + SameSite=Lax cookie, 30-day expiry. A wrong passphrase costs a fixed 250 ms.
- **Rooms**: create / list / get / archive. A room is a row plus one stable Hermes session id.
- **Messages**: `POST /api/rooms/{id}/messages` streams SSE (`delta`, `tool`, `done`, `error`) while it
  accumulates the assistant text and persists it — **even if the client disconnects mid-turn**.
- **History**: `GET /api/rooms/{id}/messages?before=&limit=` from the mirror.
- Migrations with golang-migrate, queries via sqlc, pgx. No ORM.

## Two defects found by verification, and fixed

1. **Hermes refuses duplicate session titles** — `400 Title 'P1 Referee' is already in use by session api_…`.
   Two rooms called "Work" would have failed at creation. The room keeps the name the user typed; the
   Hermes session gets `name · <first 8 of the room id>`, which is stable and unique.
2. My own referee was wrong twice: it expected the Hermes session id in the room JSON (it is deliberately
   server-side, `roomView`), and it grepped for a phrase across SSE deltas that arrive split (`"p"` +
   `"1 works"`). The referee was corrected, the product was not weakened.
