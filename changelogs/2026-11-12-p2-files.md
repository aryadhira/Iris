# 2026-11-12 — P2: files both ways

Uploads from Boss into a room, artifacts from Hermes back to Boss, one download link that works twice on a
phone.

## The contradiction we measured first

The brief's verified fact — `POST /api/sessions` accepts `system_prompt` — is true. The conclusion that this
prompt reaches a chat turn is not, in build `v0.21.6+636`.

A throwaway session was created with a six-line room prompt containing the absolute folder
`/home/…/iris-p2-probe`. The session response said `"has_system_prompt": true`. On the next
`/api/sessions/{id}/chat/stream` turn Hermes ignored it: it searched for an `outbox` folder, found none,
created `/home/aryadhira/outbox`, wrote `catatan.md` there, and did not emit a marker. `PATCH
/api/sessions/{id}` also rejects `system_prompt` (`Unsupported session fields: system_prompt`).

The same build **does** apply a per-request `instructions` string as the ephemeral system prompt. A second
throwaway session sent the identical six lines in `instructions`; Hermes wrote `outbox/catatan.md` inside
the room folder and ended with `[[artifact: outbox/catatan.md]]`. So irisd stores the prompt on the room
and sends it on every turn. The probe sessions and the stray `~/outbox` were deleted; the live `iris`
database was not touched.

This is ADR-006. It also makes the contract **editable later** without recreating the Hermes session.

## Schema (migration 000005)

```sql
ALTER TABLE rooms ADD COLUMN folder_path text NOT NULL DEFAULT '';
ALTER TABLE rooms ADD COLUMN system_prompt text NOT NULL DEFAULT '';

CREATE TABLE files (
    id uuid PRIMARY KEY,
    room_id uuid NOT NULL REFERENCES rooms (id) ON DELETE CASCADE,
    message_id uuid REFERENCES messages (id) ON DELETE SET NULL,
    source text NOT NULL CHECK (source IN ('user', 'agent')),
    name text NOT NULL,          -- display name, never a path
    path text NOT NULL,          -- relative to the room root, e.g. inbox/<uuid>-photo.png
    mime text NOT NULL,          -- sniffed, never the client's word
    size bigint NOT NULL CHECK (size >= 0),
    sha256 text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX files_room_created_idx ON files (room_id, created_at DESC, id DESC);
CREATE INDEX files_message_idx ON files (message_id);
```

`sqlc.yaml` gained a nullable-uuid override so `message_id` is `*uuid.UUID`, not `pgtype.UUID`.
`GetRoom` now also selects `folder_path` and `system_prompt`; `CreateRoom` writes them.

## Folder contract

`IRIS_DATA_DIR` (default `~/iris-data`) → `rooms/<room-id>/`:

```
inbox/    files Boss sends
outbox/   files Hermes hands over
```

Both are created before the Hermes session, so the prompt can name the real absolute path. The six lines
stored on `rooms.system_prompt`:

```
Kamu adalah Hermes, bekerja di dalam room Iris ini.
Folder room ini: <abs path>.
File yang Boss kirim ada di inbox/ — baca dengan alat file-mu.
Simpan hasil yang harus Boss terima di outbox/.
Akhiri balasanmu dengan satu baris [[artifact: outbox/<nama>]] untuk setiap file yang harus Boss terima.
Jangan menulis di luar folder room ini.
```

One guard serves downloads, artifacts and uploads: `rooms.Folder.Resolve` rejects absolute paths, any `..`
component, the root itself, empty/`.` components, and symlinks (including a symlinked parent). The test
also writes a secret into room B and proves room A cannot resolve `../<B>/outbox/secret.txt` or a symlink
to B.

## API

| Method | Path | Behaviour |
|---|---|---|
| `POST` | `/api/rooms/{id}/uploads` | one multipart file, 25 MB cap, streamed to `inbox/<uuid>-<sanitised>`, MIME sniffed from bytes |
| `POST` | `/api/rooms/{id}/messages` | `{text, attachmentIds[]}`; the human's text is stored, Hermes gets one `Lampiran: inbox/<file> (PDF, 1,2 MB)` line per file |
| `GET` | `/api/rooms/{id}/files` | everything in the room, newest first, with `source` |
| `GET` | `/api/files/{id}` | bytes, stored MIME, inline for images/PDF, attachment otherwise, `nosniff`, `Content-Length`, private no-cache |
| `DELETE` | `/api/files/{id}` | deletes the row and the bytes |
| `PATCH` | `/api/rooms/{id}/prompt` | edits the room contract for future turns (no UI yet) |

Sniffed allowlist: PNG, JPEG, WEBP, GIF, PDF, DOCX, XLSX, `text/plain`, Markdown, CSV, JSON, ZIP. Client
`Content-Type` is ignored. DOCX/XLSX are told apart from a plain ZIP by their archive entries. Rejections:
`tipe file ini belum didukung` (415) and `26,0 MB — batasnya 25 MB` (413).

After a turn, the assembled reply is parsed for `[[artifact: <path>]]` markers (spaces and `\` tolerated).
A marker whose file resolves **and exists** is stored with `source='agent'`, hashed, linked to the
assistant message, and stripped from the visible body. A marker whose file is missing stays in the body and
is logged: `artifact promised but not found`. The message DTO carries
`attachments: [{id,name,mime,size,sha256}]`.

## Web

- Composer: paperclip, drag-and-drop over the room, paste (clipboard items and files). Pending chips show
  type, name, size, a progress bar, and a remove button. Send is blocked while a chip uploads or has
  failed, and the composer says why.
- User messages: images render as thumbnails (click → lightbox); other files as a chip with type, name and
  size. An attachment-only message is allowed.
- Assistant replies: each artifact is a card with type icon, name, size and a real download anchor.
- A **File** button in the room header opens a bottom sheet on phones and a right side panel on desktop:
  every file with `Kamu kirim` / `Hermes kirim`, size, download and a two-step delete.
- Long names truncate in the chip, card and library; nothing overflows at 390×844.

## Screenshot findings (files in `changelogs/assets/`)

What looked wrong and was fixed:

1. **A transparent 1×1 fixture read as a black box.** The first browser run used a technically valid but
   empty PNG; Hermes itself answered “PNG 1×1 piksel (placeholder kosong)”. The driver now uploads a
   320×200 violet “P2” card and waits for `naturalWidth > 0`, so the thumbnail and the lightbox are real.
2. **The first lightbox check passed with `naturalWidth=0`.** It only asserted that an `<img>` existed.
   The check now waits for the image to decode before recording.
3. **There was no screenshot of the image turn.** Only the empty room and the later artifact were captured;
   `${label}-image` was added so the thumbnail and the reply are visible together.

What is intentional, not a defect:

- On desktop the second turn scrolls the conversation to the bottom, so the top of the image bubble is
  clipped in `p2-desktop-artifact.png`; that is normal scroll position, and `p2-desktop-image.png` shows
  the whole bubble.
- The phone library is a bottom sheet at 82dvh; the area above it is the blurred room, not empty UI.
- The phone header keeps the name to 42vw, truncates the topic, and shows only the File icon; that is how
  the row fits 390 px without overflow.
- Filenames truncate with a title tooltip; nothing wraps the layout.

## What is missing (deliberate)

- **No prompt-editing UI.** `PATCH /api/rooms/{id}/prompt` works, but no screen calls it.
- **No backfill for existing P1 rooms.** The migration gives them `folder_path = ''`; they can still chat
  but cannot carry files until the room is recreated or a backfill is written.
- No orphan-`.part` sweeper if irisd dies mid-upload; the temp file is inside `inbox/` and never has a row.
- No resumable uploads, no image resize/EXIF stripping, no generated thumbnails (a thumbnail downloads the
  original bytes), no virus scan beyond the content allowlist.
- No file dedupe; uploading the same bytes twice stores two rows.
- No upload of an already-library file into a new message; a file attaches to the message it was uploaded
  for.
- The six-line contract costs tokens on every turn (~100); it is not cached.

## The one place most likely to break

**Per-turn `instructions`.** It is the only thing making the folder path and marker contract reach Hermes;
the session's stored `system_prompt` is dead weight in this build. If a Hermes update renames or stops
honouring `instructions`, the first symptom is silent: Hermes writes to `~/outbox` (measured), the reply has
no marker, and Iris shows no artifact card while the turn looks successful. The cheap canary is the
acceptance script's “artifact card appears” check; in production, watch for
`artifact promised but not found` in irisd's log and for files appearing outside `IRIS_DATA_DIR/rooms/`.
Second risk, smaller: the marker parser is line-based — an inline marker or a markdown bullet
(`- [[artifact: …]]`) is left visible rather than stripped.

Real stack: throwaway database `iris_p2_mine`, data dir `/tmp/iris-data-mine`, `irisd` on :3302, preview on

Three UI defects found by reading the screenshots back, fixed here:
1. **The artifact card was clipped by the composer** — images decode and cards mount after the scroll, so the
   view was pinned above them. A `ResizeObserver` on the content now re-pins only when the reader is already
   at the bottom (measured after the fix: card bottom 626 px, composer top 733 px).
2. **An image attachment showed no filename** — a thumbnail with only the picture told the human nothing about
   the file; it now carries `name · size` over a gradient.
3. **Language drift** — Hermes opened in English before switching to Indonesian. The room contract now says to
   answer in the language Boss writes in.

## Still missing

- No thumbnails for PDFs/office files (icon + name only), no preview for text artifacts.
- No prompt-editing UI (the API accepts it). Rooms created before P2 have no folder until recreated.
- No orphan `.part` sweeper for an interrupted upload.
